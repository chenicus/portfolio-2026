Dot field — four hover treatments

Four prototypes for making the hero canvas react to the cursor, cheapest first. Same grid tokens as index.html (#d4d4d4, 26px cell, 1.4px dot) and the same bottom fade, with a stand-in for the terminal so each one is judged around the thing it has to sit behind. Move the pointer into a band to wake it; click inside 3 and 4 to drop a ring. Nothing runs until a band is hovered, and each stops once it has settled. Sliders are live — if you land on numbers you like, tell me and those become the defaults.

1 · Cursor spotlight — pure CSS

A second grid of heavier dots in the same phase as the base, revealed through a radial mask that follows the pointer. Two CSS variables per move, no canvas, no render loop. Lighting only — nothing displaces, so there is no depth to it.

2 · Magnetic field — canvas 2D

The grid is drawn rather than tiled, so every dot can leave its lattice position. Each one slides along the line from the cursor by a smoothstep falloff, and grows and darkens as it goes. Negative strength pulls instead of pushes — a dimple rather than a bulge.

3 · Ripple wave — canvas 2D

The grid as a height field. A standing wave follows the cursor, and a click drops a damped ring that travels out and dies. Height moves each dot more vertically than horizontally, which is what makes it read as a surface tilted away from you rather than a flat pattern; crests also swell and darken, so the wave catches the light. 4 · True 3D — WebGL

The same height field, but per pixel on the GPU and with no library: the grid is procedural in the fragment shader, the surface slope bends the lattice under it, and a light picks out the faces of the wave so crests brighten and far sides fall into shadow. Raw WebGL, ~120 lines, no three.js — but it is a shader living in the hero, which is a different kind of thing to own. Click the band.
